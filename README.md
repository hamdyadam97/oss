# بوابة الجمعية — موقع ولوحة تحكم

بوابة إلكترونية لجمعية غير ربحية: موقع عام ثنائي اللغة (العربية أساسية مع RTL، والإنجليزية اختيارية)، ولوحة تحكم كاملة بصلاحيات حسب الأدوار.

- **الواجهة:** React 19 + TypeScript + Tailwind CSS v4 + React Router + TanStack Query (`frontend/`)
- **الخلفية:** Django 5.2 + Django REST Framework + PostgreSQL (`backend/`)
- **التحليل والخطة:** [docs/01-analysis-and-plan.md](docs/01-analysis-and-plan.md)

> لا يحتوي الموقع على أي محتوى أو إحصائيات تجريبية. كل قسم يختفي تلقائيًا حتى تضيف الإدارة محتوى حقيقيًا من لوحة التحكم.

## التشغيل محليًا

### 1) الخلفية

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env        # ثم عدّل القيم (المفاتيح، DATABASE_URL)
python manage.py migrate
python manage.py init_site    # الأدوار، والإعدادات، ومسودتا سياسة الخصوصية والشروط
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8010
```

إن لم تضبط `DATABASE_URL`، فستُستخدم قاعدة SQLite للتطوير. للإنتاج استخدم PostgreSQL:

```
DATABASE_URL=postgres://user:pass@localhost:5432/association
```

### 2) الواجهة

```powershell
cd frontend
npm install
npm run dev          # http://localhost:5173  (يمرّر /api و /media إلى المنفذ 8010)
```

- الموقع: `http://localhost:5173`
- لوحة التحكم: `http://localhost:5173/admin`

لتغيير منفذ الخلفية: `$env:BACKEND_URL="http://127.0.0.1:8000"; npm run dev`

### الاختبارات

```powershell
cd backend; python manage.py test apps
cd frontend; npm run build
```

## بيانات تجريبية (للعرض فقط)

```powershell
python manage.py seed_demo          # ينشئ محتوى تجريبيًا لكل الأقسام، وحسابًا لكل دور
python manage.py seed_demo --clear  # يحذف كل البيانات التجريبية وملفاتها وحساباتها
```

- **المحتوى:** إعدادات الجمعية، بنرات، برامج، دورات (قادمة وسابقة بشهادات)، أخبار، معرض صور، وثائق حوكمة، إحصائيات، شركاء، مجلس إدارة، وأسئلة شائعة.
- **الطلبات:** تسجيلات في دورات، وعضويات (سارية، وقريبة الانتهاء، ومنتهية، وجديدة)، وطلبات خدمات، وطلبات تطوع وشراكة، ورسائل.
- **الحسابات:** `demo_admin` و`demo_content_editor` و`demo_training_coordinator` وغيرها، وكلها بكلمة المرور `Demo@2026pass`.
- **البيانات وهمية:** الأسماء والجهات والأرقام كلها وهمية. كل سجل يُحفظ في `demo_manifest.json`، لذلك لا يحذف `--clear` أي بيانات حقيقية تضيفها لاحقًا، ويعيد الإعدادات إلى ما كانت عليه.

> ⚠️ نفّذ `seed_demo --clear` قبل الإطلاق.

## أول خطوات بعد التشغيل

1. **الإعدادات:** اسم الجمعية، الشعار، الألوان، رقم الترخيص، جهة الإشراف، الرؤية والرسالة، بيانات التواصل.
2. **الصفحات:** راجع مسودتي «سياسة الخصوصية» و«شروط الاستخدام» واعتمدهما ثم انشرهما. النماذج العامة تربط بسياسة الخصوصية.
3. أضف البنرات، والبرامج، والإحصائيات **الحقيقية**، والوثائق، والشركاء.
4. عرّف الخدمات الإلكترونية وحقولها الإضافية.
5. أنشئ حسابات الموظفين وأسند لكل منهم دوره.

## الدورات والعضوية

**الدورات والفعاليات العلمية (`/courses`)**
- **المقاعد:** حدد عدد المقاعد للدورة. عند اكتمالها يُسجَّل المتقدمون الجدد تلقائيًا في **قائمة الانتظار**.
- **الموافقة:** خيار «يتطلب موافقة» يجعل التسجيلات «بانتظار التأكيد» حتى يعتمدها المسؤول. بدونه تُؤكَّد مباشرة.
- **منع التكرار:** لا يمكن تسجيل الهوية نفسها مرتين في الدورة نفسها. يتم التحقق ببصمة مشفرة للهوية، دون كشف الرقم.
- **الحضور الجماعي:** من «المسجلون في الدورات» حدّد الحاضرين واختر «حضر». تصدر **شهادة حضور** لكل منهم برمز تحقق فريد.
- **الشهادة:** يصل إليها المتدرب من صفحة «تتبع طلب»، ويطبعها أو يحفظها PDF. يمكن لأي جهة التحقق منها عبر `/certificates`.
- **التصدير:** قائمة المسجلين تُصدَّر بصيغة CSV تفتح في Excel، ولا تتضمن أرقام الهوية.

**العضوية المهنية (`/membership`)**
- **الفئات:** تُعرَّف فئات العضوية بمزاياها وشروطها ورسومها ومدتها، مع خيار اشتراط رقم وبطاقة التصنيف المهني.
- **التفعيل:** عند تغيير حالة الطلب إلى «عضوية سارية» يُولَّد **رقم عضوية** تلقائيًا (مثل `M2026-00001`)، ويُحسب تاريخ الانتهاء حسب مدة الفئة.
- **التجديد:** زر «تجديد العضوية» يمدد العضوية فترة كاملة من تاريخ انتهائها أو من اليوم، أيهما أبعد.
- **المتابعة:** فلتر «تنتهي خلال 30 يومًا» يعرض العضويات التي تحتاج تجديدًا، ويعرضها عدّاد في الصفحة الرئيسية للوحة.
- **منع التكرار:** لا يُقبل طلب جديد لهوية لديها طلب قائم أو عضوية سارية.

## الهوية البصرية

- **الملفات الأصلية:** `branding/logo-original.jpg` و`branding/launch-post.jpg`.
- **الملفات المشتقة:** `branding/make_assets.py` ينتج منها الشعار الدائري الشفاف (`logo.png` و`logo.webp`) وأيقونات المتصفح في `frontend/public`.
- **رفع الشعار:** `init_site` يرفع `logo.webp` تلقائيًا إن لم يكن في الإعدادات شعار.
- **الألوان:** مأخوذة من الشعار: الكحلي `#081940` والذهبي `#BB944A`، والأخضر `#085155` للعناصر الثانوية.
- **البنرات الجاهزة:** في `branding/banners/` («سلامة المرضى أولًا» و«انضم إلى مجتمعنا المهني»). تُعرض بتصميم «تصميم جاهز»: الصورة كاملة دون قص، والبانر كله رابط. على الجوال يظهر العنوان والوصف والزر نصًا تحت الصورة. لإضافة تصميم جديد: ضع ملف PNG في المجلد وشغّل `make_assets.py`، أو ارفعه مباشرة من لوحة التحكم.
- **تصحيح أخطاء إملائية في التصاميم:** `branding/fix_typos.py` يصحح «المرضي ← المرضى» و«وشيكة ← وشبكة» بتعديل النقاط فقط، دون إعادة رسم أي حرف. النسخ الأصلية محفوظة في `branding/banners/originals/`.
- **بانر بتصميم «هوية الجمعية»:** يعيد بناء تصميم «انطلقنا لنُمكّن» بالشعار والاسم والفاصل الذهبي، وتظهر الكلمة الأخيرة من العنوان بالذهبي. الصورة فيه اختيارية كخلفية خافتة.

## التهيئة للأردن

- **الهاتف المحمول:** يُقبل بصيغة 077 أو 078 أو 079 (أو +962)، ويُحفظ بالصيغة المحلية `07XXXXXXXX`.
- **الهوية:** الرقم الوطني للأردنيين، أو الرقم الشخصي لغير الأردنيين (10 أرقام).
- **الترخيص المهني:** رقم ترخيص مزاولة المهنة أو رقم العضوية في النقابة (الأطباء، أطباء الأسنان، الصيادلة، الممرضين والقابلات...).
- **ساعات التطوير المهني المستمر (CPD):** تظهر على الدورات والشهادات، وجهة الاعتماد قابلة للتعديل لكل دورة.
- **المصطلحات:** الهيئة الإدارية، والهيئة العامة، وسجل الجمعيات.
- **العملة والوقت:** الرسوم بالدينار الأردني (حتى 3 خانات عشرية)، والمنطقة الزمنية `Asia/Amman`.
- **التبرعات:** معطلة افتراضيًا. لا تُفعَّل إلا بعد الحصول على الموافقات الرسمية لجمع التبرعات.

## الأمان وحماية البيانات (قانون حماية البيانات الشخصية الأردني رقم 24 لسنة 2023)

- **رقم الهوية:** مشفّر في قاعدة البيانات (Fernet)، ويُحدَّد المفتاح عبر `FIELD_ENCRYPTION_KEY`. احتفظ بنسخة آمنة منه، فبدونه لا يمكن قراءة البيانات المشفرة.
- **المرفقات:** مرفقات المستفيدين والمتطوعين تُخزَّن في `PRIVATE_MEDIA_ROOT`، ولا تُخدَم للعامة أبدًا. تُنزَّل فقط عبر الواجهة البرمجية بعد التحقق من الصلاحية، ويُسجَّل كل تنزيل في سجل العمليات.
- **التحقق من الملفات:** يُتحقق من الامتداد والتوقيع الثنائي (magic bytes) والحجم، وتُستبدل أسماء الملفات بأسماء عشوائية.
- **بيانات مقدم الطلب:** للقراءة فقط في لوحة التحكم. لا يمكن تعديل إلا حقول المعالجة (الحالة والملاحظات).
- **التتبع العام:** يتطلب رقم الطلب ورقم الجوال معًا، ويعرض الحالة فقط.
- **الموافقة:** موافقة صريحة على سياسة الخصوصية في كل نموذج، مع حفظ وقت الموافقة.
- **الحماية من الإساءة:** تحديد معدل الطلبات للنماذج والتتبع وتسجيل الدخول، وحقل فخ (honeypot) ضد البرامج الآلية.
- **الجلسات:** جلسات HttpOnly مع حماية CSRF، وإعدادات HSTS والكوكيز الآمنة في الإنتاج.
- **سجل العمليات:** يسجّل كل إضافة وتعديل وحذف، وكل تسجيل دخول (ناجح أو فاشل)، مع المستخدم والوقت وعنوان IP. تُخفى القيم الحساسة في السجل.

## النشر على خادم (بدون Docker)

يعمل الموقع على نفس الخادم بجانب مشاريعك الأخرى، دون أن يتعارض معها:
- **الواجهة:** Nginx الموجود يقدّم ملفات الموقع المبنية (`frontend/dist`) والصور المرفوعة مباشرة.
- **الواجهة البرمجية:** Gunicorn يعمل كخدمة systemd باسم `pmpda`، على socket داخلي (`/run/pmpda/gunicorn.sock`) بدل منفذ، فلا يتعارض مع منافذ المشاريع الأخرى.
- **قاعدة البيانات:** مستخدم وقاعدة بيانات باسم `pmpda` في PostgreSQL الموجود.
- **HTTPS:** عبر certbot، كبقية المشاريع.

كل ما يُنشأ يحمل الاسم `pmpda`: مستخدم النظام، وقاعدة البيانات، والخدمة، وموقع Nginx.

**المتطلبات على الخادم (Ubuntu/Debian):**
- **البرامج:** Python 3.10 أو أحدث مع `python3-venv`، وPostgreSQL، وNginx، وcertbot، وNode.js 18 أو أحدث (لبناء الواجهة).
- **الدومين:** يشير سجل `A` لـ `pmpda.com` ولـ `www` إلى عنوان IP الخادم.

**أول مرة:**

```bash
sudo git clone https://github.com/hamdyadam97/oss.git /srv/pmpda
cd /srv/pmpda
sudo sh deploy/install.sh pmpda.com
sudo certbot --nginx -d pmpda.com -d www.pmpda.com
sudo -u pmpda backend/.venv/bin/python backend/manage.py createsuperuser
sudo -u pmpda backend/.venv/bin/python backend/manage.py seed_demo      # اختياري
```

**ماذا يفعل `install.sh`:**
1. يتأكد من وجود المتطلبات، ولا يثبّت شيئًا من تلقاء نفسه.
2. ينشئ مستخدم النظام وقاعدة البيانات.
3. يولّد `backend/.env` بمفاتيح عشوائية.
4. يبني الواجهتين.
5. يثبّت خدمة [deploy/pmpda.service](deploy/pmpda.service) وموقع Nginx من [deploy/nginx-pmpda.conf](deploy/nginx-pmpda.conf).

يمكن إعادة تشغيله بأمان: لا يغيّر المفاتيح ولا قاعدة البيانات الموجودة.

> ⚠️ **احفظ نسخة من `backend/.env` خارج الخادم.** بدون `FIELD_ENCRYPTION_KEY` لا يمكن قراءة أرقام الهوية المشفرة أبدًا.

**التحديث بعد أي تعديل:**

```bash
cd /srv/pmpda
sudo -u pmpda git pull        # المجلد ملك المستخدم pmpda بعد التثبيت
sudo sh deploy/update.sh      # المكتبات، والـ migrations، والملفات الثابتة، وبناء الواجهة، وإعادة التشغيل
```

**النسخ الاحتياطي:** `sudo sh deploy/backup.sh` يحفظ قاعدة البيانات ومجلدي المرفقات في `backups/`، ويحتفظ بآخر 14 يومًا. جدوله يوميًا عبر `sudo crontab -e`، وانقل النسخ دوريًا خارج الخادم.

**أوامر مفيدة:**
- **السجلات:** `sudo journalctl -u pmpda -f`
- **الحالة:** `sudo systemctl status pmpda`
- **إعادة التشغيل:** `sudo systemctl restart pmpda`

**ملاحظات:**
- **البيانات التجريبية على الخادم:** حسابات `demo_*` تأخذ كلمة المرور `DEMO_PASSWORD` من `backend/.env`، وتُولَّد عشوائيًا، وليست كلمة المرور المنشورة أعلاه. احذف البيانات التجريبية قبل الإعلان عن الموقع بـ `seed_demo --clear`.
- **المرفقات الخاصة:** مرفقات المستفيدين في `backend/private_media` بصلاحية المستخدم `pmpda` وحده، ولا يقدّمها Nginx أبدًا.
- **مستخدم Nginx:** الإعداد يفترض أن Nginx يعمل بالمستخدم `www-data` (الافتراضي في Ubuntu/Debian).
- **موقع البيانات:** راجع متطلبات قانون حماية البيانات الشخصية الأردني بشأن نقل البيانات خارج المملكة عند اختيار مزوّد الاستضافة وموقع الخادم.

## إضافة نموذج جديد إلى لوحة التحكم

1. أنشئ النموذج (model) في Django، ثم الـ serializer والـ viewset، وسجّله في `config/urls.py`.
2. أضف تعريفه في `frontend/src/admin/resources.ts`، فتُبنى شاشات القائمة والنموذج تلقائيًا.
3. أضف صلاحياته إلى الأدوار المناسبة في `roles.py`.
